# RetailPulse — Testing Strategy

**Version:** 1.0 | **Related:** [CODE_STYLE](CODE_STYLE.md) · [SECURITY](SECURITY.md) · [IMPLEMENTATION_PLAN](IMPLEMENTATION_PLAN.md) · [TRD](TRD.md)

Tests are how this project stays trustworthy while an AI assistant writes much of the code. A change is not done until its tests pass and the gates in §6 hold.

---

## 1. Principles

1. **Test behavior, not implementation.** Assert outputs and side effects, not private calls.
2. **Fast by default.** Unit tests need no network, no Docker and no sleeps. The whole unit suite should finish in under 60 seconds.
3. **Real dependencies where they matter.** Integration tests use a real PostgreSQL. Do not mock the database or the ORM. Mock only external boundaries (Prefect trigger, webhooks, MLflow in API unit tests).
4. **Deterministic.** Seeds fixed, no wall-clock (`as_of` is passed in), no reliance on test order.
5. **ML needs its own tests.** Leakage, determinism, metric correctness and gates are tested explicitly (§4).
6. **A failing test is a finding.** Never weaken or skip a test to get green; fix the cause or ask.

## 2. Layout, markers and configuration

```
tests/
├── conftest.py              # shared fixtures (settings, rng, tmp dirs)
├── helpers/                 # factories, stub API client, polling helper
├── fixtures/
│   ├── mini_retail.csv      # generated by scripts/make_fixture.py
│   └── golden/              # expected counts and small expected outputs (JSON)
├── unit/                    # config, security, etl, features, ml, monitoring, api (pure), dashboard components
├── integration/             # db, api, pipelines, ml registry (real Postgres, temp MLflow)
├── e2e/                     # docker compose end-to-end
└── load/                    # k6 or Locust scenarios (not run by pytest)
```

Markers: `unit`, `integration`, `e2e`, `ml` (trains models; small data), `slow` (> 10 s). Unmarked tests under `unit/` are treated as `unit`.

```toml
[tool.pytest.ini_options]
minversion = "8.0"
addopts = "-ra --strict-markers --strict-config"
testpaths = ["tests"]
markers = [
  "unit: fast tests without external services",
  "integration: needs PostgreSQL",
  "e2e: needs the full compose stack",
  "ml: trains small models",
  "slow: takes more than 10 seconds",
]

[tool.coverage.run]
source = ["src/retailpulse"]
branch = true

[tool.coverage.report]
fail_under = 80
show_missing = true
skip_covered = true
```

## 3. Test types

### 3.1 Unit
Pure functions and classes: config validation, security helpers, cleaning rules, feature builders, metrics, forecasters on tiny synthetic series, policy formulas, label mapping, CSV safety, pagination helpers.

### 3.2 Integration
- **Database:** a session-scoped fixture creates `retailpulse_test`, runs Alembic to head once; each test runs inside a transaction rolled back at the end (tests that must commit use a truncate fixture). A separate test runs `upgrade head → downgrade base → upgrade head`.
- **API:** FastAPI `TestClient` against the test database; auth via real tokens made with the test secret.
- **MLflow:** temporary SQLite backend store and temp artifact directory (not the production server).
- **Pipelines:** call the flow's underlying function; the Prefect trigger is replaced by the inline implementation.
- **Idempotency:** load the fixture twice; assert identical row counts and no duplicate keys.

### 3.3 End to end (`make e2e`)
Compose up (test profile) → create admin → upload the fixture → wait for the pipeline (poll with timeout) → train on the fixture → promote → read KPIs, forecast, customers and inventory via the API → assert expected shapes. Runs nightly and on release tags, not on every PR.

### 3.4 Dashboard
Streamlit `AppTest` per view with a **stub API client** returning canned JSON (`tests/helpers/stub_client.py`). Assert: no exceptions, key elements present, role-based visibility (viewer sees no write controls), empty/error states render.

### 3.5 Load and performance
`tests/load/` scenarios for k6 or Locust: login, overview, forecast read, customers list, inventory list at 50 concurrent users. Compare p95 with TRD §7. Run manually and in Phase 9.

## 4. ML-specific tests (mandatory)

| Test | What it proves | How |
|------|----------------|-----|
| **Leakage: features** | Features at origin `t` use only data ≤ `t` | Build features; multiply all data after `t` by 1000; features must be unchanged |
| **Leakage: churn windows** | Features ≤ T, label in (T, T+90], no overlap across split boundary | Assert on constructed tables; assert purge gap |
| **Leakage: backtest** | Training data strictly before each origin | Harness asserts `train.date.max() < origin`; test that a violating forecaster is caught |
| **Metrics correctness** | WAPE, MASE, RMSSE, bias, coverage, pinball match hand-computed values; WAPE is 0 for perfect forecasts; zero-scale series handled | Table-driven tests; Hypothesis invariants |
| **Determinism** | Same data, config and seed give the same outputs | Run twice; exact for baselines and LightGBM (deterministic settings), tolerance 1e-4 for LSTM |
| **Sanity vs baseline** | Models learn real signal | On a synthetic dataset with trend and weekly seasonality, LightGBM and Prophet beat naive; on pure noise they do not claim to |
| **Champion gate** | A bad model cannot be promoted | Inject a forecaster that predicts constants; gate rejects; promotion service refuses |
| **Intervals** | Residual-quantile intervals reach nominal coverage on synthetic data | Coverage within ±8 points of 0.80 |
| **Calibration** | Churn probabilities are calibrated on the fixture-based synthetic population | Brier score better than base-rate predictor; reliability check with tolerance |
| **Label mapping** | Segment labels are deterministic | Same centroids give the same labels; permuting cluster order does not change labels |
| **Policy properties (Hypothesis)** | Inventory math is sane | Safety stock ≥ 0; ROP ≥ μ_L; monotone in service level and in σ; order qty respects MOQ; stockout risk in [0, 1] and decreasing in inventory position |
| **Simulator sanity** | Simulator is wired correctly | Infinite stock gives fill rate 1.0; zero stock gives 0.0; same seed gives same result |
| **Idempotent scoring** | Re-scoring the same date does not duplicate rows | Run scoring twice; counts unchanged; pointer valid |
| **Failure keeps outputs** | A failed job does not move the active pointer | Force an exception mid-run; pointer and served rows unchanged |

Production quality gates (champion gate, batch reject ratio) are **application logic** and are tested here. Absolute model accuracy on the real dataset is reported in `reports/`, not asserted in unit tests.

## 5. Security tests

Security-specific tests live in `tests/unit/security` and `tests/integration/api/test_security.py`:

- JWT: expired, tampered signature, `alg: none`, wrong algorithm, missing claims, wrong role claim → 401 or 403 as appropriate.
- Passwords: hash verifies; wrong password fails; hashes differ per call (salt); plaintext never logged.
- Lockout after repeated failures; generic failure message for unknown user and wrong password.
- **RBAC matrix:** parametrized over every route × {anonymous, viewer, analyst, admin} against the table in API.md. A **route inventory test** fails if the app has a route missing from the matrix.
- **Sensitive-field scan:** walk the OpenAPI schema; no property named like `password`, `password_hash`, `secret`, `salt`, `token` in responses (except the login token).
- Upload: oversize (413), wrong extension or magic bytes (415), missing headers (422), duplicate file (200 with existing batch), XLSX with macros rejected.
- CSV export: cells starting with `=`, `+`, `-`, `@`, tab or CR are neutralized.
- Injection: SQL metacharacters and very long strings in query parameters never cause a 500.
- Headers: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` present; drift HTML served with sandbox CSP; docs routes absent when `RP_ENABLE_DOCS=false`.
- Rate limiting: login returns 429 after the limit and includes `Retry-After`.
- Pseudonymization: deterministic, salt-dependent, raw ID never present in any table or log capture.

CI also runs static and supply-chain scans (SECURITY.md §9).

## 6. Quality gates

| Gate | Threshold | Enforced by |
|------|-----------|-------------|
| Lint and format | 0 findings | `make lint` in CI |
| Types | mypy strict on `src/` | `make typecheck` |
| Import contracts | 0 violations | import-linter in `make lint` |
| Unit and integration tests | all pass | CI |
| Overall coverage | ≥ 80% (branch) | `fail_under` |
| `security/`, `ml/inventory/policy.py` | ≥ 95% | CI step with `--include` |
| `etl/`, `features/`, `ml/forecasting/{metrics,backtest,intervals}.py` | ≥ 90% | CI step |
| `api/` | ≥ 85% | CI step |
| `pipelines/` | ≥ 75% | CI step |
| `dashboard/` | ≥ 60% (smoke) | CI step |
| Security scans | no high/critical findings without a documented exception | security workflow |
| Migrations | up/down/up on empty DB | integration test |

Coverage is a floor, not a goal; a test that asserts nothing does not count (review for it).

## 7. CI mapping

| Job | Runs | Trigger |
|-----|------|---------|
| `lint` | ruff, format check, import-linter | every PR and push |
| `typecheck` | mypy | every PR and push |
| `unit` | `pytest -m "unit and not slow"` with coverage | every PR and push |
| `integration` | Postgres service container; `pytest -m "integration or ml"` | every PR and push |
| `security` | bandit, pip-audit, gitleaks, image scan | PR, push to main, weekly |
| `build` | build images (no push) | PR touching `infra/` or dependencies |
| `e2e` | compose stack, `make e2e` | nightly, release tags |

## 8. Writing good tests (conventions)

- Name: `test_<unit>_<behavior>_<condition>` (e.g. `test_wape_returns_zero_for_perfect_forecast`).
- Arrange, act, assert. One behavior per test. Prefer table-driven tests (`pytest.mark.parametrize`) over loops.
- No logic in tests (no conditionals or loops that mirror the code under test).
- Time: pass `as_of`; never read the clock. Randomness: use the `rng` fixture (seeded); never `random` without a seed.
- Waiting: use the polling helper with a timeout; never `time.sleep` in tests.
- Data: factories in `tests/helpers/factories.py`; keep fixtures tiny and readable; golden files are small and reviewed in PRs.
- Do not assert on log text. Assert on returned values, stored rows and HTTP responses.
- Network is forbidden in unit and integration tests (use a socket-blocking fixture).
- Flaky tests are bugs: fix within two working days or delete the test and open an issue.
- Every bug fix starts with a failing test that reproduces it.

## 9. Commands

| Command | Purpose |
|---------|---------|
| `make test-unit` | unit tests only |
| `make test-int` | integration tests (needs `make up` for Postgres) |
| `make test` | unit + integration |
| `make cov` | tests with coverage report and per-package thresholds |
| `make e2e` | end-to-end on the compose stack |
| `uv run pytest -k name -x -vv` | run one test and stop at the first failure |

## 10. Pre-merge checklist

- [ ] New logic has tests; bug fixes have a regression test.
- [ ] ML changes include or update leakage and determinism tests.
- [ ] New or changed endpoints are in the RBAC matrix and API.md.
- [ ] Migrations tested up and down.
- [ ] Coverage gates hold; no skipped or xfail tests added without a linked issue.
